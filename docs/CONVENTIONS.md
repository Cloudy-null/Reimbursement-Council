# Conventions

One place for how things are named, stored and configured. If you need to break a rule here, write a decision record first.

## Stack
- Python 3.12, managed with uv. Dependencies pinned in pyproject.toml and uv.lock.
- FastAPI for the API and pages. Jinja2 templates plus htmx for the screens. No frontend build step.
- Pydantic v2 for every data model in docs/DATA_MODEL.md.
- SQLite for storage, one file under data/ (not committed).
- Reader: EasyOCR (offline, Arabic and English) behind a reader adapter. PaddleOCR as an ablation. Optional Gemini API free tier vision reader behind the same adapter, off by default.
- Case reviewer: Gemini API free tier through one adapter module, optional. Model name comes from config, never hardcoded.
- No paid API anywhere. The app must run with no keys at all.
- QR decoding: OpenCV QRCodeDetector (no system packages needed). Fallback library only with a decision record.
- Tests: pytest. Lint and format: ruff. Types: mypy on core.
- CI: GitHub Actions running ruff, mypy and pytest.

## Folder map
```
reimbursement_council/
  config/        load and validate config/*.yaml and .env
  core/          pure logic: rules, council members, combine, calibrate, lanes, payout math
  adapters/      vision model, QR decoder, storage, dataset loaders
  pipeline/      wires the stages together
  web/           FastAPI routes, templates, static (tokens.css lives here)
  cli/           commands: generate data, run harness, run ablation, demo mode
config/          decision.yaml, policy.yaml, prices.yaml, experiments.yaml
data/            generated and downloaded data (gitignored)
tests/           mirrors reimbursement_council/
docs/            everything in CLAUDE.md
```

## Config files (the only place numbers live)
- config/policy.yaml: made-up policy. Claim window days (90), benefit limits per category, co-pay percents, exclusion list, network price rule.
- config/prices.yaml: reference price list per service and medicine.
- config/decision.yaml: council member weights, which members are on, calibration method, hard rule confidence floor, disagreement limit, reviewer_time_value in SAR, always_review_amount_enabled (off by default), self-fix max retries.
- config/experiments.yaml: named switch sets for each ablation (see EXPERIMENTS.md).
- Every config file is validated by a Pydantic model on load. A bad value fails loudly at startup.

## Names
- Python: snake_case for functions and variables, PascalCase for classes, UPPER_CASE for constants that are truly constant (not tunable, tunables go in config).
- Council members are named by job: document_checker, coverage_checker, price_checker, case_reviewer, history_member.
- Lanes are exactly: auto_approve, auto_reject, self_fix, human_review.
- Switches in config are named <thing>_enabled, for example qr_first_enabled.

## Data rules
- Money is stored as integer halalas (1 SAR = 100 halalas). Convert only for display. Never use floats for money.
- Dates are stored as ISO 8601 in UTC. Hijri dates are converted on read and the original text is kept.
- Every extracted field keeps: value, source (qr, vision, member_confirmed, reviewer), confidence (0 to 1), and where on the document it came from (page and box) when known.
- Scores and probabilities are floats from 0 to 1. Never percentages in storage.
- IDs are UUID strings, generated by us. Never trust an ID from a document as a primary key.
- Model output is untrusted input. Validate it against the schema. On failure, retry once, then mark the field low confidence.

## Logging
- Python logging, one logger per module. Every log line about a claim includes the claim_id.
- Never log full receipt text or patient names at info level. Debug only, and never in demo mode.

## Privacy
- Real test receipts are anonymized before they enter data/. Names and ID numbers are replaced.
- Nothing from data/ is committed, pasted into docs, or shown on slides unless it is synthetic.
